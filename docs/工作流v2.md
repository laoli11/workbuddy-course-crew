# 课程制片工作流 v2（唯一执行标准）

> 本文件是课程制片团的**唯一流程标准**。成员定义（agents/）、规范（skills/）与本文件冲突时，**以本文件为准**，并回改冲突方。
> 设计目标：换任何模型接手，都**不能**偏离要求——靠门禁和单一事实源，不靠模型自觉。
> 最后更新：2026-11-14

---

## 〇、梳理方法与依据

**方法**：事实复核 → 按环节拆"输入 / 输出 / 依赖 / 衔接" → 对照用户历史要求与踩坑档案找偏差 → 重建。

**依据（按优先级）**：
1. 用户明确指示（对话中的批评与要求）
2. `docs/踩坑经验总结.md`（已发生的 28 条真实问题）
3. 现有规范 `skills/*`（6 份）
4. 现场盘点（2026-11-14 15:55 实测）

**现场盘点的硬事实**：

| 盘点项 | 实测结果 |
|---|---|
| 7 门课文稿/配音 | 全部有；但**只有第 01 课有分镜 JSON 和字幕对齐**，02–07 课全无 |
| 成片 `04_成片/` | 7 门课全部 0 个 |
| 剪映草稿 | 第一课堆了 **11 个版本**（草稿 v1–v8、成品、成品v2、分镜版），无一个标记为当前有效 |
| 专家包 vs 仓库 | 上一轮对 4 个成员定义的修改**被反向同步覆盖丢失**；V2 色板只在专家包、仓库缺失 |
| 工具 | 10 个在仓库 `tools/`，4 个草稿生成脚本散落在临时 workspace（`make_draft_*.py`）|
| 规范 | `production-spec` 出现两个"十、"章节；同一阈值（y≤840、20 字、BGM 音量）散落在 18 处 |

## 一、复核结论：现有流程的问题

### 1. 遗漏（该有没有）

| # | 遗漏 | 后果 |
|---|---|---|
| L1 | **没有"用户确认事实"环节**（人名、头衔、渠道） | 讲师名改 5 轮、"发到群里"进了文稿 |
| L2 | **没有"权威稿锁定"环节** | 用户手改的稿被流水线覆盖 |
| L3 | **分镜无机器可读版**（第 02–07 课） | 下游只能凭记忆映射，录屏段被偷换成动画 |
| L4 | **字幕没有拆行步骤** | 一句配音 = 一条字幕，65 句超 20 字 |
| L5 | **没有版本/产物登记** | 草稿 11 个版本，用户不知道看哪个 |
| L6 | **没有"待用户录屏清单"交付物** | 用户不知道自己该录哪几段 |
| L7 | **没有同步方向约束** | 改动被反向覆盖丢失 |

### 2. 冗余（重复或可删）

| # | 冗余 | 处理 |
|---|---|---|
| R1 | 4 个 `make_draft_*.py`（lesson01 / final / aligned / storyboard）功能重叠 | 合并为 `tools/build_draft.py`，只读分镜 JSON |
| R2 | 分镜 Markdown 与 JSON 两份手写 | JSON 为源，Markdown 由工具从 JSON 生成 |
| R3 | 阈值在 18 处重复书写 | 收敛到 `skills/production-spec/thresholds.json` 一处，其他地方只引用 |
| R4 | `validate_delivery.py` 与 `review_gate.py` 部分检查重叠 | 保留分工：前者管文稿层，后者管成片层 |

### 3. 顺序不合理

| # | 问题 | 正确顺序 |
|---|---|---|
| S1 | 先配音、后定分镜 → 分镜 12 段对不上配音 8 段 | **先锁 TTS 稿 → 由同一切段函数同时决定配音段和分镜段** |
| S2 | 先做动画、后看段时长 → 10s 动画凑 60s | **先配音拿实测时长 → 再按段时长渲染动画** |
| S3 | 先出草稿、后审片 → 用户先看到不合格品 | **审片闸门 PASS 才交付用户** |
| S4 | 字幕对齐放在草稿生成之后 | **对齐在合成之前**，合成直接消费对齐结果 |

### 4. 不符合要求（规范写了但没执行）

| # | 要求 | 实际 | 根因 |
|---|---|---|---|
| N1 | 团队协作：建团队、派成员、成员产出 | 主理人一人代写全部环节 | 无检查点约束 |
| N2 | 动画前读 animation-spec 色板 | 自创红绿金配色 | 规范与执行两张皮 |
| N3 | 字级对齐（20–40ms） | 字数比例估算，偏差 1.97s | 无工具、无门禁 |
| N4 | 交付前自检 | 自报"没问题"无证据 | 门禁未强制 |
| N5 | 以认可版本为基线 | 每次推倒重来，丢 BGM | 无基线登记 |

## 二、新工作流总览

```
P0 开课登记 ──► P1 文稿锁定 ──► P2 分镜蓝图 ──► P3 配音与对齐 ──► P4 画面制作 ──► P5 合成草稿 ──► P6 审片闸门 ──► P7 交付
   主理人          文成稿           文成稿           冯佳音            影成帧          影成帧          严把关          主理人
   [G0]            [G1]             [G2]             [G3]              [G4]            [G5]            [G6]
```

**铁律**：每个阶段出口有一道门禁（G0–G6）。**门禁不 PASS，下一阶段不得开始。** 门禁是命令，不是人的判断。

## 三、逐环节定义

### P0 开课登记（主理人）

| 项 | 内容 |
|---|---|
| 输入 | 用户的开课指令、课程大纲 |
| 动作 | ① 查 `facts`：讲师名、头衔、渠道（群/客服）是否已在 `terminology.json` 确认；**未确认的一次性问用户**，不推断 ② 查用户是否已有手改稿（`spaces/` 等目录），有则登记为权威版 ③ 在 `registry.json` 建本课条目 |
| 输出 | `registry.json` 本课条目：`{lesson, authority_script, facts_confirmed: true, baseline_draft: null}` |
| 约束 | 事实类信息**只认用户确认**，禁止从 ASR 稿推断（踩坑 1.1）|
| **G0 验收** | `python tools/workflow.py gate G0 --lesson NN`：facts 已确认 + registry 条目存在 |

### P1 文稿锁定（content-director 文成稿）

| 项 | 内容 |
|---|---|
| 输入 | 原始逐字稿 / 用户权威稿 + 大纲 + teaching-spec |
| 动作 | ① **有权威稿：只允许追加规范段落，正文零改动** ② 无权威稿：洗稿 → 口播稿 → TTS 朗读稿 ③ 跑术语闸 |
| 输出 | `第NN课_口播稿.md`、`第NN课_TTS朗读稿.txt` |
| 约束 | 不得虚构人设/头衔/渠道；小任务必须可自验（踩坑 1.2、1.3）|
| **G1 验收** | `validate_delivery.py` 全绿 + 若有权威稿，`diff` 显示正文零改动 |
| **锁定** | G1 PASS 后 TTS 稿锁定。之后改文稿 = 回到 P1，下游全部作废重跑 |

### P2 分镜蓝图（content-director 文成稿）

| 项 | 内容 |
|---|---|
| 输入 | **已锁定**的 TTS 稿 |
| 动作 | ① 用 `split_text()`（与配音**同一函数**）切段 → 段数即分镜段数 ② 每段判定 `mode`（animation / recording / card）③ 填 `assets`、`hold_tail` |
| 输出 | `第NN课_分镜.json`（**唯一事实源**）；Markdown 版由工具生成 |
| 判定标准 | 观众要**照着做** → recording；要**看明白道理** → animation；只需**知道** → card |
| 约束 | **分段只能来自 split_text()**，禁止另起分段（顺序问题 S1）|
| **G2 验收** | `storyboard.py --check`：段数 = 配音切段数、全覆盖不重叠、mode 合法、动画段无 still |

### P3 配音与对齐（voice-director 冯佳音）

| 项 | 内容 |
|---|---|
| 输入 | 锁定的 TTS 稿 + 分镜 JSON |
| 动作 | ① `gen_tts.py` 按段配音 ② `align_subtitles.py` VAD 实测对齐 ③ **字幕拆行**：单条 ≤ 20 字（在标点处断）④ BGM 准备 |
| 输出 | `02_配音/第NN课_段XX.mp3` + 完整配音；`第NN课_字幕_对齐.json/.srt`；BGM |
| 约束 | **禁用字数比例估算**；配音参数固定（MiniMax speech-2.8-hd，speed 1.15）|
| **G3 验收** | 配音段数 = 分镜段数；对齐文件存在；SRT 每条 ≤ 20 字、≥ 0.2 秒/字 |

### P4 画面制作（video-director 影成帧）

| 项 | 内容 |
|---|---|
| 输入 | 分镜 JSON + **P3 实测段时长** |
| 动作 | ① 读 animation-spec 色板（V2 认证版）② animation 段：**按段实测时长渲染**（duration = 段长）③ recording 段：有素材则包装，无素材则占位 + 记入待录屏清单 ④ card 段：带轻动效 |
| 输出 | 各段动画 mp4；`第NN课_待录屏清单.md` |
| 约束 | 只执行分镜，**不改判 mode**（要改回传主理人）；禁"短动画+尾帧"、禁"短动画循环 N 次"（踩坑 2.3、2.8）|
| **G4 验收** | 每段素材时长 ≥ 段时长 − 0.2s（animation 段）；配色检查；待录屏清单与分镜 recording 段一致 |

### P5 合成草稿（video-director 影成帧）

| 项 | 内容 |
|---|---|
| 输入 | 分镜 JSON + 配音 + 对齐字幕 + 段动画 + BGM |
| 动作 | `tools/build_draft.py --lesson NN`（**唯一草稿生成入口**）|
| 输出 | 剪映草稿 `第NN课_<课名>_r<N>`（r = 修订号，单调递增）；`spec.json` 落 `04_成片/` |
| 约束 | 必须双音轨（配音 + BGM，BGM vol ≤ 0.35）；在**基线版本**上增量改，不推倒重来 |
| **G5 验收** | 视频轨总长与配音差 ≤ 0.2s；素材 100% 存在；草稿已加密 |

### P6 审片闸门（reviewer 严把关）

| 项 | 内容 |
|---|---|
| 输入 | 草稿 spec + 分镜 JSON + 字幕 + 全部门禁输出 |
| 动作 | `review_gate.py`（D2/D3/D4/D6/D8 自动）+ D1/D5/D7/D9/D10 人工判定，每项写"测量值 / 阈值 / 结论" |
| 输出 | `04_成片/第NN课_审片报告.md`（首行判定）|
| 约束 | 只认工具输出与抽帧证据；踩坑档案同类问题零容忍 |
| **G6 验收** | `review_gate.py` 退出码 0 **且** D10 分镜一致性通过 |

### P7 交付（主理人）

| 项 | 内容 |
|---|---|
| 输入 | G6 PASS 的草稿 + 审片报告 + 待录屏清单 |
| 动作 | ① 登记 registry：`current_draft = r<N>`，旧版标记 superseded ② 向用户交付 |
| 交付物（固定 3 件）| ① 当前有效草稿名（唯一一个）② 审片报告（含偏差说明）③ 待录屏清单（段号 + 录什么 + 注意事项）|
| 约束 | **不许交付未过 G6 的东西**；有偏差必须明说 |

## 四、执行保障机制（防偏离的关键）

### 4.1 单一事实源表

| 事实 | 唯一来源 | 禁止 |
|---|---|---|
| 讲师名/术语/数字 | `skills/terminology-spec/terminology.json` | 从 ASR 稿推断 |
| 分段与制作方式 | `第NN课_分镜.json` | 手写映射 |
| 字幕时间 | `第NN课_字幕_对齐.json` | 字数估算 |
| 配色 | `animation-spec` §7 V2 色板 | 自创配色 |
| 阈值 | `skills/production-spec/thresholds.json` | 各文件各写一份 |
| 当前有效版本 | `registry.json` | 凭记忆说"最新版" |

### 4.2 同步方向（单向，防覆盖）

```
开源仓库 D:/workbudyy/workbuddy-course-crew   ← 唯一编辑位置
        │ tools/sync_plugin.py（单向推送，带漂移检测）
        ▼
专家包 plugins/my-experts/plugins/course-crew   ← 只读，禁止直接改
        │ register_expert.py
        ▼
WorkBuddy 运行时
```

**铁律**：只在仓库改。`sync_plugin.py` 检测到专家包比仓库新时**拒绝覆盖并报错**，人工合并后再推。

### 4.3 团队协作检查点（N1 的解）

主理人每阶段必须：建团队 → 派对应成员 → 收成员产出 → 跑门禁 → 汇报用户。
**主理人不得代写成员的专业产出**。单环节小修（Workflow 2）可直调单个成员，但同样要过该环节门禁。

### 4.4 换模型接手清单（每次会话开头必做）

```bash
python tools/workflow.py status --lesson NN   # 1. 看本课处于哪个阶段、哪道门禁卡住
cat docs/踩坑经验总结.md                        # 2. 读踩坑档案
python tools/workflow.py gate <当前阶段> --lesson NN   # 3. 跑当前门禁，从卡住处继续
```

不读 status 就动手 = 违规。

## 五、验收标准总表

| 门禁 | 命令 | PASS 条件 |
|---|---|---|
| G0 | `workflow.py gate G0` | facts 已确认、registry 条目存在 |
| G1 | `validate_delivery.py` | 术语/教学法全绿；权威稿正文零改动 |
| G2 | `storyboard.py --check` | 段数一致、全覆盖、mode 合法、动画无 still |
| G3 | `workflow.py gate G3` | 配音段数一致、对齐文件存在、字幕 ≤20 字且 ≥0.2s/字 |
| G4 | `workflow.py gate G4` | 动画时长 ≥ 段长 − 0.2s、待录屏清单一致 |
| G5 | `workflow.py gate G5` | 总长差 ≤0.2s、素材全在、已加密、双音轨 |
| G6 | `review_gate.py` + D10 | 退出码 0、分镜一致 |
