# 整期编排规范（Episode Assembly）

> 本规范管**整期层面**：把各段串成一条视频时的规则。单段写法看 animation-spec 与 course-visual-library。
> 方法论吸收自 FredTalk《整期编排》，垂直化到 WorkBuddy 课程（深色科技风）。

## 一、录屏段怎么包装（WorkBuddy 实操课核心）

WorkBuddy 课程大量内容是实操（下载/安装/登录/积分/配置），录屏包装质量直接决定成片观感。

- **一进来就能读**：要读的字 ≥ 24px（1080 画布）。整窗缩进大窗字会小到 10px，必须**推近到正在发生的区域**（常见 1.6–2.4 倍）。整窗原样播放是最大失分点。
- **镜头跟着口播走**：讲到哪里推到哪里。每次移动约 **0.6 秒到位，停稳读 0.85–1.65 秒**，再走下一处。单次移动超过 **1.4 秒**就是"慢推"。
- **纯滚动不超过 2 秒**；第一帧就开始动。长页面先跳到要讲的位置。
- **每 2–3 秒要有一次可见变化**：点击、输入、结果出现、组件接管、镜头换焦。没有新变化就加组件或剪短。
- **交互要演出来**：
  - 点击：光标移过去 + 点击环 + 按钮状态变化（配 click 声）
  - 输入：对话框弹出，打字机跟口播打出，再点发送（配 typing 声）
  - 扫码：登录框放大 + 二维码高亮 + 手机图标扫入
  - **避坑点（如"别装 C 盘"）：停顿强调 + 局部放大 + 警示标签**
- **录屏只截口播讲到的那部分**，不带入前一段对话。

## 二、段间交接表（核心规则）

- **上一段末帧 = 下一段首帧**：同一个对象、同一位置、同一尺寸，靠一个连续动作交给下一段。**禁用**淡入淡出、整屏左右平移、PPT 式划走。
- 写代码前在简报里列出每个接缝的交接表：

| 接缝 | 上一段末态 | 下一段首态 | 动作 | 音效 |
|---|---|---|---|---|
| 段2→段3 | 机器人落地 | 左右卡片并排 | 机器人缩小让位，卡片错峰飞入 | woosh |

- **常用交接动作**：胶囊放大成黑幕再开窗；卡片变形成浏览器窗口；页面压成一条线再展开；输入框对输入框匹配剪辑。
- 渲染后看接缝前后各 0.5 秒**动态**，不只比首尾两张静帧。

## 三、全片组件去重

- **讲解结构类组件全片只出现一次**：路线图、方法卡、对比卡、问答类。后面再讲同一结构换一种表达。
- **呈现手法去重**：同一种运镜套路（如"缩进产品截图 → 标注 → 推近某区"）全片只完整用一次。
- 出关键帧前把全片所有段用到的组件列成表，查重复。

## 四、强调方式

- **不用紫框、黑框**。指出页面某处优先用：
  - **局部蒙版（Spotlight）**：把其余压暗 0.6，目标保持原亮
  - 阴影抬起、毛刷高亮
- **毛玻璃别做成一成不变**：同一样子不在相邻几处连用；变化来自内容。
- 高亮要停到那句口播说完，至少停稳 **1.5 秒**。
- 胶囊、卡片、标签放在目标旁边，不挡住正在讲的内容。

## 五、排版底线（每张关键帧都查）

- 关键内容 **y ≤ 900**（1080 画布），给字幕条留位；左右至少 80px。
- 同组卡片同尺寸、顶对齐、等间距；整体构图居中，不偏一边留空。
- 重点信息不缩角落：结论胶囊放画面正中或紧贴对象上下沿，字号 ≥ 48px。
- 大字单独停着也要有第二个变化；两组信息不要一上一下同时进场。
- 一屏信息太密（超 4 块）就镜头逐块推近，不平铺。

## 六、动态自检（motion_audit 阈值）

渲染后抽帧检查，以下四种是**阻止正式成片**的：

1. **定格/干等**：画面 3 秒以上不变
2. **缓慢漂移**：长时间无目的慢移
3. **单次运动过长**：一次推近/移动超过 1.4 秒
4. **纯滚动过长**：页面滚动超过 2 秒

> 数字滚动、图表生长、B-roll 等有意连续动作可豁免，但需记录理由。
> 关键判据：口播里的动作词（弹出、连线、落地、点击）说到时画面必须当场发生。

## 七、可读性自检（readability）

- 一帧里文字框 ≥ 8 个、而高度 ≥ 24px 的框面积占比 < 45%，算"看不清"；连续 3 秒以上即返工。
- 报出来先问：这几秒观众需要读界面里的字吗？需要读就推近；不需要读（只表现"有工具在运行"）且结论已由大字给出，可豁免。

## 八、关键阈值速查表

| 项目 | 数值 |
|---|---|
| 要读的字最小 | 24px（1080 画布）|
| 录屏推近倍率 | 1.6–2.4 倍 |
| 单次镜头移动 / 到位 | 约 0.6 秒；超 1.4 秒 = 慢推 |
| 停稳阅读时长 | 0.85–1.65 秒 |
| 纯滚动上限 | 2 秒 |
| 可见变化频率 | 每 2–3 秒一次 |
| 定格判罚线 | 画面 3 秒以上不变 |
| 高亮最短停稳 | 1.5 秒 |
| 开场到位 | 0.5 秒内 |
| 结论胶囊字号 | ≥ 48px |
| 字幕区避让 | 主体最低点 y ≤ 840（animation-spec）|

## 九、程序化机器闸（交付前脚本自检，不靠人工抽帧）

渲染后跑脚本自动检测，任一触发即返工（参考 video-talkcraft 三重验收、huashu `om check`/`om qa`）：

| 检测项 | 规则 | 脚本思路 |
|---|---|---|
| 静止检测 | 画面 3 秒以上不变（定格/干等）| 相邻帧差 < 阈值的连续时长 |
| 慢推/纯滚动 | 单次运动 > 1.4 秒、滚动 > 2 秒 | 光流/位移分析 |
| 可读性 | 文字框 ≥8 个且高度 ≥24px 占比 < 45% | OCR 框检测（macOS Vision）|
| 裁切/遮挡/低对比 | 字被裁、被元素遮挡、对比度过低 | 边界检测 + 前景检测 |
| 音效在场 | 每个 cue 对应音效能量 > 阈值 | 音效轨分段能量验证 |
| 单帧空档/硬切 | 一闪而过的异常帧、无转场硬切 | 抽帧对比 + 接触表 |

> 机器闸只抓"技术缺陷"，"美不美"仍需人工看图确认。两者分开记录，技术 PASS 不等于视觉通过。
